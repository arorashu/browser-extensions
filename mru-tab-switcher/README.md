# MRU Tab Switcher

Switch to the most-recently-used tab in Chrome / Chromium / Safari with a
keyboard shortcut. Inspired by Firefox's `browser.ctrlTab.sortByRecentlyUsed`
behavior, which the other browsers don't ship.

Two commands:

- **Switch to most recently used tab (instant toggle)** — one-shot ping-pong
  between the two most recent tabs. Hit it twice to flip back. Window-scoped:
  it never jumps to a tab in another browser window.
- **Open recent-tabs picker** — a small popup window listing the recent tabs
  in the current window with favicons + titles. Re-pressing the shortcut walks
  the highlight through the list. Enter / click commits, Esc / focus-loss
  cancels.

The toggle and the picker are independent commands; bind one or both as you
like in `chrome://extensions/shortcuts` (or Safari Settings → Extensions).

## Install in Chrome / Chromium

1. Visit `chrome://extensions/` (or `chromium://extensions/`).
2. Enable **Developer mode** (top right).
3. Click **Load unpacked**, pick this folder (`mru-tab-switcher`).
4. Visit `chrome://extensions/shortcuts` to bind the keys. Suggested:
   - Toggle: `Ctrl+1`
   - Picker: `Ctrl+Q`
5. Leave the scope on **In Chrome** (not Global). Tab switching has no
   business firing while you're in another app.

Chrome's shortcut UI accepts only letters, digits, F-keys, and a small set of
named keys (Comma, Period, etc.) — apostrophe, backtick, etc. are silently
rejected. Pick from the supported set or remap at the OS level (Karabiner).

## Install in Safari

The `mru-tab-switcher-safari/` sibling directory contains an Xcode project
generated by `safari-web-extension-converter`. It **references** the files in
this folder rather than copying them, so edits here flow into both browsers.

1. Open `mru-tab-switcher-safari/MRU Tab Switcher.xcodeproj` in Xcode.
2. Select the macOS scheme, build & run (`Cmd+R`). The wrapper app launches.
3. Quit the app, then in Safari → Settings → Extensions, enable
   "MRU Tab Switcher".
4. Assign keyboard shortcuts in the same Settings → Extensions panel.

For unsigned/development use you'll either need to enable "Allow unsigned
extensions" in Safari → Develop menu (resets each Safari restart), sign with
a free Apple ID in Xcode (lasts 7 days), or use a paid Apple Developer
account for permanent signing.

## Permissions

- `storage` — keeps the MRU stack and picker state across service-worker
  restarts via `chrome.storage.session`. Nothing persists to disk; everything
  is wiped when the browser restarts.
- `tabs` — needed to read tab titles, URLs, and favicons in the picker. The
  extension never sends data anywhere; reads are entirely local.

## Behavior notes

- MRU is window-scoped: pressing the toggle in window A only ever lands on
  another tab in window A. The picker opened from window A only lists tabs in
  window A. Same as Firefox.
- The picker excludes itself from the MRU stack (filters out non-`normal`
  windows entirely).
- The picker waits for an explicit Enter / click / Esc — there's no
  modifier-release auto-commit. See `background.js` for the rationale; can be
  added if you want it.

## Development

A Playwright-based end-to-end test is in `scripts/test_mru.py`. It launches
Chromium with this extension loaded (in either the bundled Playwright
Chromium or your system Chromium), exercises the MRU stack and picker, and
asserts on observed behavior:

```bash
# Run against Playwright's bundled Chromium (default)
uv run --with playwright python scripts/test_mru.py --headed

# Run against your installed Chromium
uv run --with playwright python scripts/test_mru.py --headed \
    --browser /Applications/Chromium.app/Contents/MacOS/Chromium
```

15 assertions covering the toggle, picker open/walk/commit cycle, tab close
recovery, and multi-window scoping.

## Known gaps

- No extension icons yet — the Safari converter warns about this. The
  extension works without them; Safari just shows a default placeholder.
- Picker doesn't render tab thumbnails. Chrome's API can only screenshot the
  active tab, so showing thumbnails of others would require silently cycling
  tabs which is too disruptive. Favicons + titles are usually enough.
- No tap-to-toggle / hold-to-walk distinction in the picker. The instant
  toggle command covers the quick-flip case; the picker covers the
  walk-through case. Both can be bound to different shortcuts.
